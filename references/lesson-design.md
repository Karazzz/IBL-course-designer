# 单节课设计Recipe（lesson_spec）

## 适用场景
设计或修改一节课：研究问题、学生活动、课堂推进、评价；优先基于已有 `course_spec` 设计；没有课程规格时，先确认是否需要先做课程级设计，或按暂定假设设计单课并明确标注。

## 输入
按 skill 主文档第 4 节输入原则执行：优先使用已有 `course_spec`、`project_state` 与用户提供的信息，不重复询问；可暂定的直接暂定并标注；需要询问时一次集中询问。

## 设计流程
### 1. 位置与目标
先读取已有 `course_spec`，明确本节课：位于哪个模块、课程第几课时；对应哪个模块级子问题；承接了前面哪些知识、方法或经验；

### 2. 确定研究问题
一节课围绕1 个主要的、可探究的课时级研究问题展开。研究问题应与 `course_spec` 中对应课时的 `research_question` 保持一致。

研究问题必须基于 OpenAlex 检索锚点形成：
- 没有 `course_spec` 或主题为新主题时，必须先按 `course-design.md` 1.1 的规则调用 `openalex_search_works` 做一次轻量检索，再形成课时研究问题，检索结果写入本节 `research_anchor`；
- 已有 `course_spec` 时，沿用课程级检索锚点，从 `research_anchor` 中摘录与本课相关的来源写入本节 `research_anchor`，不重复检索；
- 锚点随 01 教案渲染在“一 研究问题”下方。

### 3. 设计核心学生任务
先设计学生这一节课真正要完成的核心任务，再设计教师怎么教。核心任务应足够支撑本节课的大部分时间，以学生实际动手和思考为主体。任务必须留有一定的学生自主空间。在以下至少一个环节允许学生做出自己的选择：
- 提出猜想；
- 选择变量；
- 选择材料；
- 设计实验；
- 设计作品；
- 确定测试方法；
- 解释结果；
- 提出改进方案。
教师提供必要的约束、方法和安全支架，但不把完整答案和操作步骤提前给出。

### 4. 设计证据与学生产出
根据本节课在整套课程中的位置、研究问题和核心任务，从学生证据卡库中**动态选择必要的卡片**。每节课最多使用2张卡片作为学案。AI而应先判断：本节研究问题 → 学生核心任务 → 必须产生什么证据 → 哪张卡最能帮助学生产生或整理该证据。例如本节任务是比较不同光照条件下植物幼苗的生长，可以选择S01,S05。

| 编号 | 名称 | 主要用途 |
|---|---|---|
| S01 | 事实 / 猜测 / 证据卡 | 区分观察到的事实、自己的猜测和证据来源 |
| S02 | 问题漏斗与 HMW | 从宽泛问题逐渐缩小为可探究、可测试的问题 |
| S03 | AI 协作核验单 | 记录 AI 建议、核验方式以及学生自己的最终取舍 |
| S04 | 变量与公平测试 | 识别自变量、因变量、控制变量、对照和重复 |
| S05 | 实验 / 测试方案蓝图 | 明确材料、步骤、测量方式、分工和安全检查 |
| S06 | 原始数据表 | 根据实验自主设计表头并记录原始数据，不预填结果 |
| S07 | 创意八格 | 在短时间内快速产生多种不同方案 |
| S08 | 用户旅程 / 操作流程 | 分析使用过程中的困难、需求和改进机会 |
| S09 | 同伴反馈单 | 基于作品和证据提出有效之处、疑问与改进建议 |
| S10 | 展品标签 | 用简洁语言呈现问题、方法、证据、结论和观众互动 |

卡片设计尽量使用图示、表格、绘图区、勾选、排序、数据记录等方式，减少大段文字填写；给学生留下自主表达空间，不把正确答案预先写进模板；能由学生实际使用，并成为后续讨论、比较、改进或结论的依据；
原则上，课程越往后，卡片数量越少、开放程度越高。

### 6. 设计教案
教学过程应尽可能让学生经历实验激疑（Experimental Disruption / Cognitive Conflict in Experiments），即，通过设计出乎意料的实验现象，打破学生或研究者的原有认知，从而激发强烈求知欲和探究兴趣。

教师的主要作用是设计情境、任务与学习支架，在关键困难处提供方法、工具、案例或追问，避免直接替学生完成问题定义、实验设计和判断。课程应允许试错和失败，并通过多轮测试、比较和修改体现研究的迭代性。知识和技能宜在解决问题的过程中按需引入，鼓励跨学科调用，而非先集中讲完知识再开展活动。

如用户要求教案严格对应国家、地方或学校课程标准，应明确告知：当前不支持产出经过严格课标对标或合规认证的教案。可以参考用户提供的课标内容、学习目标或具体条款进行设计。

> 优秀简略教案示例：
> 周末没人浇水，怎么让教室绿植活下来？
> 对象： 五—七年级
> 课时： 90 分钟启动课
> 模块任务： 班级有 6 盆绿植，周末无人照看，经常出现缺水或浇水过量。学校希望学生设计一种不用电、成本不超过 20 元、能够稳定维持两天供水的方案。
> 四个环节：第一，真实情境与问题定义（15分钟）：呈现教室绿植周末无人浇水这一真实需求，让学生明确任务、讨论“什么才算成功”，形成成本、供水稳定性、植物状态等评价标准；第二，快速探究与方案设计（25分钟）：学生围绕滴灌、毛细供水等可能方案开展小实验，提出可测量的问题，并据此形成初步设计；第三，原型制作与测试迭代（35分钟）：小组制作原型，测量供水量、漏水情况等数据，通过改变水位、材料、结构等条件进行压力测试，根据证据修改方案；第四，真实部署与研究延伸（15分钟）：各组将改进后的装置用于真实植物，预测48小时后的结果，确定后续观测指标和记录方式，为下一课的数据分析、失败解释和再次优化留下真实研究任务。

### 7. 设计单课行为观察评价
AI根据本课的学习目标、研究问题、核心学生任务，生成约 **4–6 条具体、可直接观察的典型学生行为**。例如：
- [ ] 提出了一个可以通过实验验证的猜想；
- [ ] 主动鼓动小组成员参与合作；
- [ ] 多次主动发言；
- [ ] 提出了好问题；

教师课堂中只需在观察到对应行为时勾选。要求行为必须具体、可见；不使用“理解了”“掌握了”“态度良好”等无法直接观察的表述；教师可选填极少量备注，不要求逐项写评语。

### 9. 资源和差异化
根据核心任务统一检查实施条件。明确每组材料及数量、共用设备、场地条件、课前教师准备、图片、视频或其他资源需求。

每份教案必须在 `resources.teacher_prep` 或 `resources.media` 中明确提示教师课前查找相关视频材料，至少包含：视频主题（与本课研究问题或核心现象直接相关）、中英文检索关键词建议、建议时长与类型（科普讲解 / 实验演示 / 真实案例等），并注明教师需自行核实视频可获得性与来源。本 skill 不代为下载或生成视频，只提供查找指引。

通过任务开放度进行差异化，避免简单设计成做得快的学生多做几道题：
- 基础支持：方法提示、半结构化记录表、示例、材料限制；
- 拓展挑战：增加变量、提高精度、改变条件、要求进一步优化或解释。

### 10. 形成 lesson_spec
按 `schemas/lesson_spec.schema.json` 形成或更新 `lesson_spec`。同步登记到 `project_state`。

## 修改已有课时
- 保留用户已确认内容，只修改受影响的环节、材料与评价；
- 修改后重新核对各环节时间合计与整体推进是否仍然成立；
- 不默认重新生成整节课。
