# 整套课程Recipe（course_spec）

## 适用场景

用于设计或修改整套研究性学习课程 / 课程模块，比如从主题、问题或已有材料生成整套课程；调整课程主线、模块、课时序列、最终任务或评价体系。不适用只设计单节课。单节课优先读取已有 `course_spec`，见 `lesson-design.md`。

## 核心设计原则
### 真实问题牵引
   - 从真实现象、生活需求、科学问题、工程挑战或社会情境出发；
   - 驱动问题应允许学生通过自己的探究、实验、调查、设计或制作获得答案，而非查到标准答案即可完成。

### 研究牵引学习
先让学生接触问题，在解决问题过程中暴露知识和能力缺口，再通过学习、实验和工具补足。前期可以提供较多任务、方法和示例；随课程推进逐渐减少支架，让学生承担更多问题定义、方案选择、证据判断和改进决策。

### 允许试错，必须迭代
失败、异常结果和方案失效都是研究过程的一部分；不要求每次活动成功，但必须要求学生记录、分析并据此调整。

### 评价真实成长
关注学生问题意识、探究实践、证据使用、反思改进、合作交流和自主性的发展。


## 输入
遵循 Skill 主文档的输入原则，优先使用用户已提供的信息和 `project_state` 中的确认内容；一次集中询问，并必须问用户`audience`、`duration`、`resources`、`final_deliverable`。分级`b_level`根据`audience`的信息合理推理，判定方法见下方设计流程。不重复询问已有信息；可合理暂定的条件直接采用，并写入 `assumptions`。

重点确认：
| 条件 | 对应字段 |
|---|---|
| 课程尺度 | `scale` |
| 年级 / 年龄 | `audience` |
| 总课时与单课时长度 | `duration` |
| 主题 / 初始问题 | `theme` |
| 课程目标 | `objectives` |
| 人数与分组 | `audience` |
| 场地、设备、材料、预算 | `resources` |
| 最终实验 / 作品 | `final_deliverable` |
| 分级 | `b_level` |

## 课程总体结构
整套课程必须形成从“有支架的学习”走向“自主完成研究闭环”的进阶结构。
### 前 75%：探索与能力建构
用于完成：
- 进入真实情境，产生兴趣与问题；
- 建立必要的背景知识；
- 学习研究方法、实验方法或工具；
- 完成若干局部探究、实验、调查或制作任务；
- 积累后续综合任务需要的数据、技能和经验；
- 逐渐减少教师支架，提高学生自主决策比
前 75% 不应主要由讲授构成。每个关键知识或方法原则上都应通过学生的观察、操作、实验、比较、数据分析、调查、设计或讨论被使用一次。

### 最后 25%：综合应用小闭环
**整套课程最后约 25% 的课时必须用于完成一个小型但完整的实验、研究任务或作品。**
按整课时计算时，可将约 25% 向上取整，并保持任务完整性。
例如：
- 8 课时课程：最后 2 课时；
- 12 课时课程：最后 3 课时；
- 16 课时课程：最后 4 课时。

一个合格的小闭环至少包含：**问题 / 目标 → 方案设计 → 实施 / 制作 → 测试或收集证据 → 分析判断 → 改进或形成结论 → 表达成果**
最终成果可以是小型实验、模型或装置、解决真实问题的方案。

## 设计流程
### 0. 根据用户的输入为课程定级
根据用户确认的 `audience` 信息，给该课程分级，即，给字段`b_level`填入从1到4之间的一个数值。以下是1到4级的学生画像
| b_level | 学生画像 |
|---|---|
| 1 | 1.具备一定的科研科创兴趣（有意愿积极参加科研或科创活动、课堂积极参与、主动提问，对科研科创呈正面态度、无排斥或抵触情绪）；2. 能够提出一个具体、可操作的科研科创问题；3. 能够基本掌握课程要求的基础知识与技能（如：文献查阅、实验设计、原型设计、数据分析工具等）；4. 能够敢于提出自己的看法，将知识与想法运用于科研科创实践；5. 能够基本具备团队合作的沟通、表达、分享、协作能力。 |
| 2 | 1. 在b1的基础上，具备强烈的科研科创志趣、课程投入度高、主动性突出、有意愿继续在科研科创领域进行进一步探索；2. 能够将所学知识和技能转化为解决日常挑战问题的能力。3. 具备独立完成一个科研科创项目的能力或经历。等级能力考核参考指标：1）独立性，学生独立完成或在团队中发挥主要作用；2）新颖性，能够提出一定新意的项目方案；3）价值性，项目方案展现出解决问题的指向和潜力；4）完整性，项目方案结构基本完整，项目实施具备完整流程，形成结题报告。 |
| 3 | 1. 在B2的基础上，有清晰明确的科研志向、极强的积极主动性投入度高、有志于投身科研科创事业或对未来有明晰的规划；2.有一年以上科研科创实践经历；3. 能够独立完成具有较高挑战性的任务，并取得高水平的成果。4.具有高能力或高创造力特征，包含但不限于以下情况之一：1）在某一领域有远超同龄人的见识、天赋或专长；2）高创新性的代表性作品；3）国内外权威赛事中获得高水平奖项，主要贡献者；4）公开在学术期刊发表论文或取得发明专利；5）其他体现杰出创新能力或高能力表现的证据。 |
| 4 | 1. 在B3的基础上，有清晰明确的科研志向、极强的积极主动性投入度高、有志于投身科研科创事业或对未来有明晰的规划；2.有一年以上科研科创实践经历；3. 能够独立发现或定义挑战问题，提出创新研究解决方案并取得高质量成果，达到专业入门水平。 |


### 1. 确定课程驱动问题
优先从真实科研前沿、产业问题或现实需求中寻找课程主题，并逐步形成：真实问题 → 课程驱动问题 → 模块子问题
#### 1.1 发现真实问题
必须先调用 `openalex_search_works` 进行一次轻量检索（默认步骤，无需用户提示），为课程找到真实研究锚点，而不是完成完整文献检索
* 根据课程领域生成简洁的英文研究关键词；
* 前沿选题可优先限制到近 3–5 年；
* 通常查看返回的前 5 条结果即可，不进行系统性文献综述；
* 找到真实且适合转译的研究主题后立即进入课程设计；
* 若工具调用失败或结果明显不适合，可换一次关键词；仍无合适结果则使用其他可信来源或已有可靠知识继续，不阻塞课程生成。
* 若检索条件不可用，可依据已有可靠知识继续设计，但避免使用“最新研究表明”等需要实时证据支持的表述。

可参考其他来源：
* Nature Index Topic Explorer：https://www.nature.com/nature-index/topics/topic-explorer
* Nature Research Highlights：https://www.nature.com/nature/articles?type=research-highlight
* Nature Research Briefing：https://www.nature.com/nature/articles?type=research-briefing&year=2026&utm_source=chatgpt.com
* 其他当前可用的高质量网页、学术或产业信息源。

#### 1.2 将前沿问题转化为学生可研究的问题
不要直接把高难度科研课题、论文标题或产业任务交给学生。应寻找其中学生能够真实研究的那一层问题。要根据用户选择的学段调整问题、变量和研究方法的复杂度：

* **小学**：直接可观察现象；以单一主要变量和简单测量为主；
* **初中**：研究变量关系；引入控制变量、重复实验和基础数据分析；
* **高中**：可以涉及多变量、机制解释、模型、公开数据或较复杂实验方法。

不要机械套用学段规则，应结合学生基础、课程时间、设备和场地进一步调整。

#### 1.3 可行性判断
最终学生研究问题应尽量满足：
* 来自真实现象、科研问题或产业需求；
* 学生能够实际观察、实验、调查、测试或分析；
* 能够产生可比较的证据或数据；
* 难度符合目标学段；
* 能在现有课时、设备、材料和预算下完成；
* 不能仅靠搜索资料直接得到答案。
如果原始问题过大或过难，继续缩小研究尺度，直到学生能够真实开展研究。

最终形成真实问题 → 课程驱动问题 → 模块子问题

确定后逐一自查：课程驱动问题、各模块子问题、各课时研究问题能否追溯到 1.1 的检索锚点；不能追溯的，补一次检索或调整问题。向用户呈现 course_spec 时简述锚点来源（论文标题 / 年份 / 关键词）。

### 2. 确定最终小闭环
优先设计课程最后 25% 要完成的综合任务，再反推前面的课程。前 75% 的课程内容原则上都应对最终任务具有直接或间接支撑作用。

### 3. 定义学习目标
学习目标的表述应采用国家课程标准中的规范术语和能力表述，并与相应学段要求、b_level匹配。目标不写成“了解、掌握、提高兴趣”等难以观察的笼统表述，而应使用提出、识别、设计、测量、比较、分析、解释、建构、制作、测试、改进、交流等可观察、可评价的行为动词。目标可从科学观念、科学思维、探究实践、态度责任等维度组织，并明确学生将在什么情境下、运用什么知识或方法、完成什么行为以及形成什么表现。
好的目标示例：
学生能够基于植物生长的真实现象，提出水分影响植物生长的可探究问题；运用控制变量方法设计对照实验，持续记录植物生长数据；通过比较和分析实验结果解释水分与植物生长的关系，并根据证据反思实验设计、提出改进方案。

### 4. 设计进阶路径
把课程拆成连续推进的模块与课时。每个模块由之前定义的子问题（模块级）牵引。比如：
**真实情境**
→ **发现问题**
→ **局部探索**
→ **知识 / 方法补充**
→ **更深入的探究**
→ **综合应用**
→ **完整小闭环**

避免每节课彼此独立； 连续教授知识，最后突然布置一个“大项目”；前面的活动与最终作品没有关系。


### 5. 设计学生任务
设计每节课的学生任务。每节课应由一个可探究的课时级问题牵引，并配置足以支撑完整课时的核心任务。任务应以学生实际操作为主体，优先采用观察、实验、测量、调查、设计、制作、测试、数据分析和改进等活动，而不是把课堂拆成大量讲授与问答。教师讲授只用于提供必要的背景知识、方法和安全支架。
适当加入真实实验视频、科学现象图片、工程案例、显微图像等视觉材料，用于激发问题、比较现象或提供研究线索。任务设计还应保留一定的开放空间，避免所有学生按照同一份步骤得到同一个结果；在研究问题、变量选择、材料组合、方案设计或作品形式上，至少提供一个可由学生自主决策的环节，使学生真正成为方案设计者和问题解决者。

> 优秀任务示例：
> 研究问题：怎样设计一架飞得更远的纸飞机？
> 学生任务：先观看不同飞机和机翼形态的短视频、图片，学生观察并提出影响飞行距离的猜想。各组自主选择一个变量，如机翼宽度、机头配重或尾翼形状，设计两种以上纸飞机并开展多轮试飞，测量飞行距离、稳定性并记录数据。根据证据判断哪种设计更有效，修改自己的方案后再次测试。最后展示最优版本，并用实验数据解释“为什么这样改”。教师提供基本测量方法和安全要求，但不提供统一设计图。

### 6. 设计前后测
评价应基于b_level学生画像，与学习目标和学生任务同步设计。整套课程使用前后测和单课行为观察的互补证据。关于单课行为观察，见lesson-design.md。整套课程必须在第一节课开始阶段和结课阶段各安排一次5道题、总分20分、答题时间不超过20分钟的测试，必须直接依据已经设计好的课程course_spec.schema生成。可参考samples/前测-AI科学研究入门.docx
每道题的情境必须取自"driving_question"的真实研究，禁止虚构人名（如小明、小红）和假设情境。以开放简答题、解释题、情境应用题为主，重点考察学生能否用自己的语言解释概念、建立关系，并把知识用于一个简单的新情境；前测与后测原则上使用相同核心问题或等值问题，以便比较真实变化。前后测的题目应该直接或间接考察学生以下维度：
- 内生动力：判断学生是否从一开始的“感兴趣”，转变为“内生动力被点燃”，学习过程是否由外部推动逐渐转向由兴趣、责任感和成就感驱动的自主投入。是否在好奇心的驱动下，在感兴趣的领域表现出钻研精神，自发地希望提升专业水平，在特定课题上钻得很深 。
- 研究能力：学生的学术潜力、逻辑推理与系统思维是否得到成长。是否建立了对“研究”的真实理解，能够辨识在有限约束条件下具有可操作性的科研课题。是否养成了证据导向的思维习惯，以及记录、复盘、协作、质疑与迭代的专业素养
- AI协同和批判思维。是否学会了将 AI 作为“科研学伴”，执行文献分析、实验方案优化、图像识别以及复杂数据的清洗与可视化，并会对AI生成的答案更有怀疑和批判思维
- 团队协作能力：是否学会并愿意团队协作、是否在团队里找到了完美适合自己的位置
- 表达能力：识别学生对学术表达的自信程度和熟练度

### 7. 检查资源与安全
确认：

- 材料与设备是否可获得；
- 时间是否足以完成观察、实验或迭代；
- 班额与分组是否可实施；
- 预算是否合理；
- 是否存在实验、工具、用电、生物、化学或户外安全风险。

### 9. 形成 course_spec
按照 `schemas/course_spec.schema.json`形成课程信息，在 `project_state` 中登记版本及确认状态。将 1.1 的检索结果写入 `research_anchor`（keywords + sources），渲染脚本会将其逐条列在 00 课程大纲“四 课程驱动问题”下方。


## 修改已有课程

修改已有课程时：

- 保留用户已经确认的内容；
- 优先局部修改，不默认重做整个课程；
- 如果修改主问题、目标、总课时或最终任务，应检查整个课程序列是否仍然成立；
- 如果课程原本没有最后 25% 的综合应用小闭环，应优先重新调整课时结构补入；
- 不应简单在原课程末尾附加一个作品，而应检查前面的知识和活动是否真正为该任务提供支撑。
